1. Base model: a CNN trained from scratch

A conventional three-block convolutional network with no augmentation or regularisation sets the reference point.

  • Validation accuracy 15.7% and macro-F1 0.139. That is about 2.7x better than guessing (5.9%), but far too inaccurate for a product.
  • Clear overfitting: training accuracy reached 27.6%, a gap of 12 points to validation. With about 70 photos per dish, the network memorises the photos instead of learning what each food looks like.

2. Improving performance

Each step tackled a specific weakness found in the previous model or in the Milestone 1 analysis.

What the comparison shows
  • Augmentation and regularisation fix overfitting: the train–validation gap fell from 12 to 3 points. However, a model trained from scratch on about 1,200 photos cannot learn enough about food, so accuracy stayed at 14.9%.
  • Transfer learning made the biggest difference. Even with the backbone frozen, accuracy jumps to 35.7%. Fine-tuning adds more because the pretrained features adapt to food textures.

4. Final model selection

Selected: MobileNetV2, fine-tuned. Rule: highest validation macro-F1, so every dish counts equally (as decided in Milestone 1). If two models are within one F1 point, the smaller model wins, because NutriScan runs on the phone. The model was then evaluated once on the held-out test set:

  • Test accuracy 44.1%, macro-F1 0.438, top-3 66.0%. The test score is in line with validation (44.3%), which confirms it generalises.
  • Strongest dishes: french fries (0.70), pizza (0.64), ice cream (0.59). Weakest: nachos (0.26), apple pie (0.29), onion rings (0.31).
  • Most frequent confusions are look-alike dishes, the same groups flagged in the Milestone 1 EDA:
    • falafel → predicted as tacos (5x)
    • apple pie → predicted as pancakes (4x)
    • nachos → predicted as tacos (4x)
    • spring rolls → predicted as pancakes (4x)
    • nachos → predicted as waffles (4x)

6. Business interpretation: what difference this project makes

  • Faster logging, better retention. Manual logging (search, scroll, select) takes 30–60 seconds per item and is the main reason users abandon diet apps. A photo with at most one confirmation tap cuts this to a few seconds.
  • Recommended product flow. Auto-log when confidence is high; otherwise show the top-3 suggestions (right 66.0% of the time). This keeps calorie errors low while still removing most manual work.
  • Low running cost. The selected model is 9 MB and runs on the phone, so there is no server cost per photo, results are instant and the photos never leave the device (a privacy selling point).
  • Data flywheel. Every user confirmation or correction is a new labelled photo. Retraining on these improves the weakest dishes over time.

7. Limitations and next steps

  • Training budget: models were trained on CPU with a reduced budget (96 px images, 3–8 epochs). Accuracy is therefore a lower bound; the notebook's GPU settings (160 px, more epochs) should be used for the production model.
  • Scope: 17 dishes on a capped working set. Next, train on the full dataset and extend to the 101 Food-101 categories and local cuisine.
  • Look-alike dishes: collect more examples for the confused pairs and use higher resolution or a larger backbone for them.
  • Nutrition: link each label to a nutrition database (e.g. USDA) and add portion-size estimation to turn a dish name into calories and macros.
  • Multi-item plates: classify every box found by the Milestone 1 detector, not only the main one, and sum the calories.
